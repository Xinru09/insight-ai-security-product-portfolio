一、需求简介

本文档用于确认 INSIGHT“AI 漏洞分析报告”需求，并作为方案评审、交互设计、研发实现和测试验收的共同依据。功能通过固定任务流把平台漏洞事实、企业资产上下文和可信安全知识组织为可追溯报告。

1. 需求背景及价值

Week1 竞品分析显示，成熟漏洞运营平台的重点已从单纯展示漏洞列表，转向资产关联、风险排序、协同处置、复测闭环和统计报告。INSIGHT 已具备资产、漏洞、检测、工单和报告模块，但安全运营人员生成专项分析报告时仍需跨多个页面手工整理。

Week2 落地方案明确：AI 更适合承担风险解释、修复建议和内容整理，系统继续负责关键数字和业务状态。由此，本需求选择“生成漏洞分析报告”作为 AI Demo 方向。

一句业务目标
帮助安全运营人员基于 INSIGHT 平台事实和可信知识，在 3 分钟内生成一份可审核、可追溯、可用于真实漏洞研判的分析报告。

2. 需求范围

范围内（一期）范围外（暂不做）
从漏洞列表选择分析对象；配置报告；检索可信知识；生成七章节报告；展示引用和待确认项；人工审核；导出 PDF。自动修改等级/VPT/状态；自动安装补丁；自动创建和派发工单；自动复测和关闭；开放式聊天；接入未审核互联网内容。

3. 名词定义

名词定义
VPTINSIGHT 用于漏洞处置优先级表达的业务字段，本功能只读取、不修改。
平台事实来自漏洞、资产、组织、工单和检测模块的确定性字段及规则计算结果。
可信知识厂商公告、权威漏洞库、INSIGHT 已审核知识和内部修复经验。
待确认项因版本缺失、来源冲突或匹配不足而不能形成确定结论的信息缺口。

二、需求目标及优先级

1. SMART 目标

序号需求描述衡量标准优先级
1完成“选择—配置—生成—审核—导出”主流程。核心流程完成率 100%P0
2保证关键平台事实准确且可追溯。CVE、等级、VPT、状态、资产、组织准确率 100%P0
3保证修复结论有可信来源。补丁、版本、命令和利用结论引用有效率 100%P0
4降低安全运营人员报告编写时间。单漏洞报告完成时间下降 60%，目标 3 分钟内P1
5验证报告是否可用于真实研判。专家判定建议可执行率 ≥85%；试点“愿意使用”≥80%P1
6形成报告版本和用户反馈闭环。确认、修改、重生成、导出均可审计P2

2. 目标用户与场景

角色核心任务本期权限
安全运营人员（一期核心）研判漏洞、组织影响面、形成修复依据并输出报告。在原有权限范围内生成、编辑、审核和导出。
安全负责人查看风险结论、优先级依据和管理摘要。查看与确认，不因 AI 获得额外数据权限。
资产负责人/修复人员获取修复、缓解和复测要求。查看所属资产相关内容。
平台管理员配置模型、知识源与审计策略。不自动获得业务数据权限。

三、产品及需求详述

1. 产品概述与功能结构

产品位于 INSIGHT 报告中心，不建设独立聊天页。功能按“输入范围—配置任务—可信生成—人工审核—输出使用”组织。

AI 漏洞分析报告：以当前用户权限为边界的任务容器
分析对象区：漏洞搜索、筛选、多选、资产/组织范围统计
报告配置区：受众、章节、深度、知识截止时间、报告名称
AI 生成区：读取平台事实、检索可信知识、结构化生成、校验
报告内容区：执行摘要、技术分析、企业影响、优先级、修复、复测、引用
审核与输出区：在线编辑、质量检查、待确认项、确认版本、PDF 导出

4. 功能详述

VR-01 选择分析对象

P0
用户场景安全运营人员在风险管理中发现严重漏洞，希望生成专项分析报告。
输入/前置条件用户已登录，拥有报告中心和目标漏洞查看权限；目标漏洞未删除。

流程说明

  1. 进入报告中心并打开“AI 漏洞分析报告”。
  2. 按名称、CVE 或资产 IP 搜索，按等级、状态筛选。
  3. 选择一个或多个漏洞，系统实时计算去重资产数和组织数。
  4. 范围非空且权限校验通过后进入配置页。
界面主要功能点交互逻辑实现逻辑
选择分析对象搜索、筛选、多选、范围统计勾选后右侧即时更新；清空后下一步禁用。后端按用户权限检索；最多 20 条漏洞、200 台资产；统计使用去重 ID。
范围摘要显示漏洞、资产、组织数量及已选项可逐项移除。每次变更重新校验权限和对象有效性。

VR-02 配置报告

P0
用户场景同一漏洞报告可能用于安全运营、管理汇报或技术修复，用户需要调整表达重点。
输入/前置条件已选择至少一个有权限查看的漏洞；范围未超过上限。
界面主要功能点交互逻辑实现逻辑
受众选择安全运营、管理汇报、技术修复单选；切换后展示对应说明。只改变提示模板和章节权重，不改变平台事实。
报告结构选择七类章节执行摘要、企业影响面、证据与引用不可取消。前后端同时校验必选章节。
分析策略报告名、截止时间、内容深度名称 1—100 字；默认当天和标准分析。配置作为生成任务参数和审计快照保存。

VR-03—VR-06 平台事实、知识检索与 AI 生成

P0
用户场景用户希望看到 AI 正在使用什么数据，以及为什么某些结论可以确定、某些需要确认。
输入/前置条件生成配置校验通过；业务 API、知识索引和模型服务可用。

平台事实

对象字段来源
漏洞ID、名称、CVE/CWE、等级、VPT、状态、发现时间风险管理
资产IP/域名、产品版本、核心属性、暴露面资产中心
组织与处置组织、负责人、工单、SLA、复测结果组织/工单/检测
知识厂商公告、权威库、审核状态、适用版本知识库与情报库

检索与生成规则

  • 检索顺序：精确 CVE → 产品与版本 → CWE/漏洞类型 → 关键词或向量召回。
  • 返回 3—5 条最相关且已审核的知识；未审核互联网内容不得进入生产上下文。
  • 补丁编号、版本、命令和利用结论必须包含引用 ID。
  • 版本缺失、来源冲突或匹配不足时生成“待确认项”，禁止强结论。
  • 输出必须通过 JSON Schema、事实一致性、引用完整性和必填章节校验。
异常页面表现实现逻辑
知识未命中不输出具体补丁/版本，提示人工补充。生成可确认部分并创建待确认项。
来源冲突展示冲突来源。禁止确定结论，记录冲突。
模型超时保留范围和配置，可重试。任务失败，不展示半成品。
权限变化终止生成并提示重新选择。清除任务上下文与缓存。

VR-07—VR-08 报告审核、确认与导出

P0
用户场景安全运营人员需要核对事实和修复建议，处理信息缺口后将报告用于真实研判。
输入/前置条件报告生成成功；当前用户仍拥有报告中全部对象的访问权限。

报告固定结构

  1. 执行摘要
  2. 漏洞技术分析
  3. 企业影响面
  4. 处置优先级依据
  5. 修复与缓解建议
  6. 复测与验收标准
  7. 证据与引用
界面主要功能点交互逻辑实现逻辑
报告正文章节导航、在线编辑、重新生成AI 段落可编辑；平台事实只读。保存 AI 原稿、人工修改差异和版本。
质量检查事实校验、引用完整、待确认项三项人工审核未完成时不能确认。前后端门槛校验；确认记录人员、时间和版本。
导出草稿/确认版 PDF草稿带“未经确认”标识。导出前再次鉴权；无权字段停止导出。

验收标准

  • 七个必需章节完整展示，目录可跳转。
  • 平台事实准确率与引用有效率均为 100%。
  • 未完成三项人工审核时不能确认报告。
  • 确认后记录版本、确认人和时间；修改后回到待审核。
  • 导出内容与页面一致，草稿与确认版标识明确。

四、其它产品需求

1. 性能需求

指标要求
任务创建点击生成后 3 秒内返回任务 ID 和首个进度事件。
单漏洞标准报告P95 ≤ 30 秒。
20 条漏洞批量报告P95 ≤ 90 秒。
报告页面首屏P95 ≤ 2 秒。
PDF 导出P95 ≤ 15 秒。

2. 监控需求（数据埋点）

事件触发时机关键属性
ai_report_scope_selected完成范围选择漏洞数、资产数、组织数
ai_report_generate_start/result开始/结束生成受众、深度、耗时、状态、错误码、待确认数
ai_report_citation_open查看引用来源类型、来源 ID
ai_report_edit/confirm/export编辑、确认、导出章节、修改量、版本、草稿/确认版
ai_report_feedback用户反馈愿意使用/不愿意使用、原因

3. 兼容性需求

  • 支持 INSIGHT 当前适配的 Chrome、Edge 最近两个企业版本。
  • 支持 1280×720 及以上桌面分辨率；移动端可浏览，不作为一期核心生产入口。
  • 离线 Demo 为单 HTML 文件，无需安装依赖或启动服务器。

4. 安全、权限与合规

  • 权限过滤必须在查询和上下文组装前完成，禁止先查全量数据再依赖模型隐藏。
  • 跨租户、跨组织数据不得进入 Prompt、缓存、日志或引用。
  • 企业数据不得用于通用模型训练；敏感字段沿用平台脱敏策略。
  • 外部知识视为不可信内容，隔离其中指令以防提示词注入。
  • 生成、编辑、确认和导出均写入审计日志。

五、风险分析（可选）

风险可能性严重性预防与应对策略可应对性
资产版本缺失导致适用范围误判高高条件化表达；生成待确认项；推动资产字段治理。中
知识过期或来源冲突中高来源分级、截止时间、审核状态、冲突检测；禁止强结论。中
模型编造补丁、版本或命令中高Schema、引用强约束、规则二次校验、金标测试集、人工审核。高
数据越权或跨租户泄露低高权限前置过滤、租户隔离、导出二次鉴权、审计告警。高
用户过度信任 AI 结论中高草稿标识、待确认项、人工审核门槛、禁止自动写操作。高
报告过长影响决策效率中中摘要先行、按受众组织内容、章节导航和深度设置。高

用户验证方案

不问“你喜不喜欢”，验证真实使用意愿。
请 1—3 名安全运营或相关人员完成一次固定漏洞研判，并回答：“你愿不愿意明天就用它处理一个真实漏洞？”记录完成时间、无法理解的字段、被修改最多的章节、待确认项是否有效，以及最终是否愿意使用。
